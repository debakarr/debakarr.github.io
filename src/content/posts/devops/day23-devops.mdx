Terraform configuration files are usually written in HCL (HashiCorp Configuration Language), though JSON works too. HCL is recommended: all the documentation uses it, and it reads more easily than JSON. The file extension is `*.tf`.

A configuration file typically holds resource definitions, variable definitions, data sources, and other infrastructure components. Here is an example `main.tf` that runs an nginx Docker container (taken from the official docs):

```tf
terraform {
  required_providers {
    docker = {
      source  = "kreuzwerker/docker"
      version = "~> 3.0.1"
    }
  }
}

provider "docker" {}

resource "docker_image" "nginx" {
  name         = "nginx"
  keep_locally = false
}

resource "docker_container" "nginx" {
  image = docker_image.nginx.image_id
  name  = "tutorial-debakarr"

  ports {
    internal = 80
    external = 8000
  }
}
```

The commands you will use most often:

- `terraform init` — initializes the working directory, downloading required providers and setting up the backend.
- `terraform validate` — checks the configuration files for syntax errors and other issues.
- `terraform plan` — builds an execution plan showing what Terraform will do to reach the desired state.
- `terraform apply` — executes the plan and changes the infrastructure accordingly.
- `terraform destroy` — deletes the infrastructure Terraform manages.

What each command does against the `main.tf` above:

1. `terraform init` sets up the working directory and installs the Docker provider (`kreuzwerker/docker`).
2. `terraform validate` confirms the configuration is syntactically valid and processable.
3. `terraform plan` compares current state with desired state and reports that a Docker image and container will be created.
4. `terraform apply` downloads the `nginx` image, creates the container, and maps container port 80 to host port 8000.
5. `terraform destroy` removes the container and image — useful for cleanup or starting fresh.
